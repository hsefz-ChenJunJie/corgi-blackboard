# 课堂测试清单模板

每个测试版复制本模板生成 `docs/testing/<版本>-classroom-checklist.md`，并按该版本实际可见的界面改写场景。清单只记录课堂真实设备上的结果。开发者文档审读、自动化测试或回放都不能填进“实际”栏，也不能把未测改成通过。

## 1. 版本绑定

| 字段 | 值 | 来源 |
| --- | --- | --- |
| 版本号 | `<version>` | 诊断窗口“版本：”一行 |
| 发布通道 | `Test` | 诊断窗口“版本：”一行 |
| 构建 commit hash | `<PENDING-PACKAGE-BINDING>` | `release-manifest.json` 的 `commit` |
| exe SHA256 | `<PENDING-PACKAGE-BINDING>` | `SHA256SUMS` |
| 安装方式 | ZIP 解压 / 安装器（勾选一项） | 测试者填写 |

打包前这些值保持 `<PENDING-PACKAGE-BINDING>`。拿到安装包后，先核对诊断窗口显示的版本和 `SHA256SUMS`。对不上就停止测试，并在反馈里写明。

## 3. 结果填写规则

- “预期”是二值判断，只能结论为“是/否”。
- “结果”只能填 `通过`、`失败`、`未测` 三者之一。拿不准就填 `未测`，再在备注里写原因。
- 每个场景写下当时的诊断会话 ID，在诊断窗口“会话：”后面能看到。
- 失败项按 `docs/testing/feedback-guide.md` 导出反馈包，把包名写进备注。
- 本版本没有实现的功能列在“未实现”里。它们不算失败，也不用测。

## 4. 场景表

每个场景一行，格式如下：

| 编号 | 场景 | 步骤 | 预期（是/否） | 实际 | 结果 | 会话 ID | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| S01 | `<场景名>` | 1. … 2. … | `<可观察的是/否判断>` | | 未测 | | |

版本清单必须覆盖以下场景，每项各占一行，不合并：

1. 断网冷启动
2. 手指书写、切换颜色和粗细
3. 实体笔书写、切换颜色和粗细
4. 不同尺寸橡皮局部擦断笔画
5. 书写中加入第二个触点
6. 擦除中加入第二个触点
7. 双指改变距离，不发生缩放
8. 双指四向平移
9. 鼠标滚轮与 Shift+滚轮
10. 多个资料窗口拖动、改尺寸、最小化、从软件入口恢复、关闭、层叠
11. 平移黑板时资料窗口位置不动
12. 长图、宽图、小图的普通滚动
13. 长图在普通模式先滚动到非零阅读偏移，记下阅读位置、窗口位置和比例并做批注；进入铺满后滚动到不同的阅读偏移，记下铺满阅读位置；最小化并恢复后仍为铺满模式且保留铺满阅读位置；退出铺满后恢复先前普通模式的阅读偏移、窗口位置和比例，批注仍对齐
14. 系统 DPI 缩放与镜像投屏
15. 连续一节课使用后反馈
16. 坏文件与取消导入
17. 正常退出后日志完整
18. 异常退出后下次仍能导出已有日志
19. 日志管理、导出与故障提示

第 17 到 19 项只检查诊断日志有没有保留下来。本版本不保存板书，也不承诺恢复板书。

## 5. 未实现（不算失败）

列出本版本界面上没有入口的功能，例如 PDF、PPT。

## 6. 隐私与离线

软件不联网上传，也没有在线问卷或遥测。反馈包只在测试者手动导出后才会生成，保存在测试者选择的位置，由测试者自己决定交给谁。反馈包包含已记录的触点坐标。
