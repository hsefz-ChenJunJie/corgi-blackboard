# 课堂反馈指南

这份指南讲怎么把课堂上遇到的问题交给开发者。整个过程不需要联网，软件也不会自动上传任何东西。

## 1. 遇到问题时先记下

- 发生时间，大概到分钟。
- 你做了什么（步骤），你期望看到什么（预期），实际看到了什么（实际）。
- 对应清单里的场景编号，例如 S16。

不用当场填完。下课后再整理也可以，日志会留在本机。

## 2. 找到会话 ID 和版本

1. 点工具栏的“诊断”。
2. 窗口上方“版本：”一行写着版本号、通道和当前会话 ID，例如 `版本：0.1.0-test.1 / Test / 会话：…`。
3. 下方列表是本机保存的各次会话，每行显示时间、大小和状态（“正常”或“异常/未完成”）。

把版本和会话 ID 抄进清单对应行。

## 3. 导出反馈包

1. 在会话列表里选中出问题的那次会话。可以按住 Ctrl 多选。
2. 在“复现步骤”里写步骤，在“预期/实际”两个框里分别写预期和实际。
3. 读一下提示：反馈包会包含已记录的触点坐标。
4. 点“导出所选反馈”，选保存位置。也可以先在路径框里填好完整路径。
5. 看窗口底部的提示：
   - “反馈包已导出，可离线附加给开发者。”表示导出成功。
   - “反馈包已导出，但包含不完整日志；请把此状态告知开发者。”表示包已生成，但日志有缺口，请在反馈里提一句。
   - “导出已取消，未生成成功反馈包。”或“导出失败：…”表示没有可用的包，把这句话抄下来。
   - 在保存对话框里点了取消，就什么都不会生成。

反馈包是一个 zip。里面有各会话的日志、`environment.json`（系统、架构、DPI、设备名）、`classroom-checklist.md` 和 `manifest.json`（包含你填写的步骤、预期和实际）。用 U 盘或你习惯的方式交给开发者就行。

## 4. 交付内容

每个问题交以下几样：

- 填好的课堂清单，或者对应的那一行。
- 反馈包 zip 的文件名。
- 没测的场景保持“未测”，不要改成“通过”。

## 5. 示例：坏图片

1. 点“打开图片”，选一个其实不是图片的文件，比如把一个写了几行字的 `.txt` 改名成 `.png`。
2. 底部会显示“仅支持 PNG、JPEG 和 BMP 图片。”，并且不会打开资料窗口。
3. 把这句提示原样写进“实际”。如果它没出现，或者软件打开了空窗口、卡住、闪退，就算失败。
4. 打开“诊断”，选当前会话，填步骤、预期、实际，然后导出。
5. 清单 S16 行填会话 ID 和包名。结果按你看到的情况填写，没做就是“未测”。

## 6. 示例：日志写不进去

如果日志目录写满或被系统拒绝写入，软件会继续工作，诊断窗口上方会显示“捕获状态：降级”，可能还带“（存在缺口或未完成尾部）”。底部可能出现以 “Diagnostics degraded:” 开头的英文说明。

1. 把这两行原样抄进“实际”。
2. 仍然试着导出。成功后若提示“包含不完整日志”，这是预期行为，照实写。
3. 导出也失败的话，抄下“导出失败：…”整句，再点“打开日志目录”，把 `%LOCALAPPDATA%\CorgiBlackboard\Logs` 下对应的会话文件夹整个复制给开发者。

## 7. 不会发生的事

- 软件不联网，没有在线问卷，没有遥测。
- 重启后黑板是空白的。本版本只保留诊断日志，不恢复板书，这不算故障。
